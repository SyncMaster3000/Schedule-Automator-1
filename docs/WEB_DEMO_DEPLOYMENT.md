# Публикация веб-демо

## Что подготовлено

Веб-интерфейс и API запускаются одним сервисом и используют один HTTPS-адрес.
При старте сервер:

1. проверяет обязательные настройки;
2. применяет недостающие миграции PostgreSQL;
3. подключает защищённые cookie-сессии;
4. отдаёт собранный веб-интерфейс;
5. корректно завершает соединения при остановке контейнера.

В корне проекта находится переносимый `Dockerfile`. Он не содержит паролей,
токенов или адреса базы.

Также подготовлен необязательный `render.yaml` для размещения приложения и
PostgreSQL в регионе Frankfurt. В нём автоматические публикации отключены, а
база закрыта от внешних подключений. Указанные планы являются платными:
перед импортом шаблона нужно проверить актуальную стоимость в кабинете Render.

## Требования к размещению

- контейнерный хостинг с Node.js 22 или поддержкой Docker;
- PostgreSQL с резервным копированием;
- постоянный HTTPS-адрес;
- не менее 1 ГБ оперативной памяти для импорта и экспорта документов;
- возможность задавать секретные переменные окружения.

## Обязательные настройки

| Переменная          | Назначение                                               |
| ------------------- | -------------------------------------------------------- |
| `DATABASE_URL`      | секретная строка подключения к PostgreSQL                |
| `DEMO_ADMIN_TOKEN`  | случайный служебный секрет длиной не менее 32 байт       |
| `SALES_CONTACT_URL` | ссылка для кнопки приобретения: HTTPS, email или телефон |
| `NODE_ENV`          | значение `production`                                    |
| `PORT`              | порт сервиса; обычно его назначает выбранный хостинг     |

`DATABASE_URL` и `DEMO_ADMIN_TOKEN` нельзя записывать в Git, Dockerfile,
переписку с клиентом или интерфейс браузера.

## Первый запуск

1. Создать пустую базу PostgreSQL и включить резервное копирование.
2. Собрать контейнер из корня проекта.
3. Задать обязательные переменные как секреты хостинга.
4. Запустить контейнер и дождаться сообщения о применении миграций.
5. Проверить адрес `/api/healthz`.
6. Создать первый аккаунт операторской командой из `WEB_DEMO_AUTH.md`.
7. Пройти сценарий: вход, смена пароля, работа с расписанием, выход и окончание
   срока доступа.

При использовании Render эти ресурсы можно создать импортом `render.yaml`.
