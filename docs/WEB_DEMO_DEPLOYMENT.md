# Публикация веб-демо

## Что подготовлено

Веб-интерфейс и API запускаются одним сервисом и используют один HTTPS-адрес.
При старте сервер:

1. проверяет обязательные настройки;
2. применяет недостающие миграции PostgreSQL;
3. подключает защищённые cookie-сессии;
4. отдаёт собранный веб-интерфейс;
5. удаляет демо-пространства после назначенного срока хранения;
6. корректно завершает соединения при остановке контейнера.

В корне проекта находится переносимый `Dockerfile`. Он не содержит паролей,
токенов или адреса базы.

Также подготовлен необязательный `render.yaml` для бесплатного веб-сервиса
Render в регионе Frankfurt. PostgreSQL размещается отдельно на бесплатном
тарифе Neon, а его строка подключения вводится как секрет при импорте
Blueprint. Автоматические публикации отключены.

Эта конфигурация предназначена только для демонстрации. Бесплатный сервис
Render засыпает при отсутствии обращений, а первый вход после простоя может
занять около минуты. Для постоянной эксплуатации нужно перейти на платный
веб-сервис и настроить резервное копирование базы.

## Требования к размещению

- контейнерный хостинг с Node.js 22 или поддержкой Docker;
- PostgreSQL; для демонстрации подходит Neon Free;
- постоянный HTTPS-адрес;
- 512 МБ оперативной памяти для базовой демонстрации, 1 ГБ рекомендуется для
  импорта и экспорта больших документов;
- возможность задавать секретные переменные окружения.

## Обязательные настройки

| Переменная                         | Назначение                                           |
| ---------------------------------- | ---------------------------------------------------- |
| `DATABASE_URL`                     | подключение ограниченной рабочей роли PostgreSQL     |
| `MIGRATION_DATABASE_URL`           | подключение владельца только для миграций при старте |
| `REQUIRE_RESTRICTED_DATABASE_ROLE` | запрет запуска под ролью с `BYPASSRLS` (`true`)      |
| `DEMO_ADMIN_TOKEN`                 | случайный служебный секрет длиной не менее 32 байт   |
| `DEMO_CLEANUP_ENABLED`             | фоновая очистка после срока хранения (`true`)        |
| `DEMO_CLEANUP_INTERVAL_HOURS`      | период очистки, по умолчанию 6 часов                 |
| `DEMO_CLEANUP_BATCH_SIZE`          | размер безопасного пакета, по умолчанию 25           |
| `SALES_CONTACT_URL`                | HTTPS, email или телефон для покупки                 |
| `NODE_ENV`                         | значение `production`                                |
| `PORT`                             | порт сервиса; обычно его назначает хостинг           |

Обе строки базы и `DEMO_ADMIN_TOKEN` нельзя записывать в Git, Dockerfile, логи,
переписку с клиентом или публичный интерфейс приложения. Их вводят только в
защищённые поля секретов хостинга. После миграций сервер удаляет
`MIGRATION_DATABASE_URL` из своего окружения и открывает рабочий пул только по
`DATABASE_URL`.

## Первый запуск

1. Создать пустую базу PostgreSQL и включить резервное копирование.
2. Создать отдельную роль приложения без `SUPERUSER` и `BYPASSRLS`, выдать ей
   CRUD-доступ к таблицам и доступ к последовательностям.
3. Собрать контейнер из корня проекта.
4. В `MIGRATION_DATABASE_URL` задать владельца базы, а в `DATABASE_URL` —
   ограниченную роль приложения.
5. Задать остальные обязательные переменные как секреты хостинга.
6. Запустить контейнер и дождаться сообщений о миграциях и ограниченной роли.
7. Проверить адрес `/api/healthz`.
8. Создать первый аккаунт операторской командой из `WEB_DEMO_AUTH.md`.
9. Пройти сценарий: вход, смена пароля, работа с расписанием, выход и окончание
   срока доступа.

Фоновая очистка запускается сразу после старта контейнера и затем по интервалу.
Это важно для Render Free: сервис может спать, но просроченные данные будут
удалены при следующем пробуждении. Отдельный платный cron для этого не нужен.

При использовании Render веб-сервис создаётся импортом `render.yaml`.
Обе строки подключения Neon и случайный `DEMO_ADMIN_TOKEN` длиной не менее
32 байт нужно ввести в защищённые поля Blueprint. Основной контакт кнопки
покупки уже настроен на Telegram.
