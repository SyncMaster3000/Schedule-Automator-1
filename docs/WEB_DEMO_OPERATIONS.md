# Эксплуатация веб-демо

Этот регламент предназначен для владельца Schedule Automator. Клиентам нельзя
передавать служебный токен, строку подключения к базе или команды из этого
документа.

## Секреты оператора

На компьютере оператора временно задаются:

- `DEMO_API_URL` — `https://schedule-automator-demo.onrender.com`;
- `DEMO_ADMIN_TOKEN` — тот же секрет, что задан в Render;
- `DATABASE_URL` для команды резервного копирования — строка владельца Neon,
  заданная локально только на время запуска команды. На Render одноимённая
  переменная содержит ограниченную рабочую роль.

Секреты нельзя сохранять в Git, скриншотах, переписке с клиентом или текстовых
файлах внутри проекта.

## Выдача доступа

Из корня проекта:

```powershell
pnpm demo:create -- --organization "Название учреждения" --login demo.client --name "Имя пользователя"
```

Команда выведет логин, временный пароль и дату окончания. Передать их клиенту
нужно по личному каналу. При первом входе клиент обязан заменить пароль.

Для пилота рекомендуется:

- демонстрация — 7 дней;
- хранение после окончания — 30 дней;
- отдельная организация и отдельный логин для каждого учреждения;
- не загружать реальные персональные данные слушателей: приложению для показа
  достаточно учебных программ, ФИО преподавателей и обозначений аудиторий.

## Автоматическая очистка

Сервер проверяет срок хранения при каждом старте и затем каждые 6 часов, пока
работает. Удаление организации каскадно удаляет её программы, расписания, архив,
справочники, аудит и сессии. Пользователь удаляется только если он больше не
состоит ни в одной организации.

Предварительный просмотр:

```powershell
pnpm demo:cleanup
```

Подтверждённое удаление:

```powershell
pnpm demo:cleanup -- --confirm
```

Команда не позволяет удалить активный доступ или данные до назначенной даты
хранения.

## Резервное копирование

Neon Free предоставляет ограниченное восстановление по времени и один snapshot.
Перед первым пилотом нужно создать ручной snapshot в разделе **Backup &
Restore** консоли Neon. Актуальные ограничения указаны на
[странице тарифов Neon](https://neon.com/pricing).

Для отдельной переносимой копии используются официальные утилиты PostgreSQL
`pg_dump` и `pg_restore`:

```powershell
pnpm demo:backup
```

Команда:

1. не передаёт пароль в аргументах процесса;
2. создаёт архив формата PostgreSQL Custom;
3. проверяет читаемость архива через `pg_restore --list`;
4. по умолчанию сохраняет его в исключённую из Git папку `backups`.

После проверки файл нужно перенести из проекта на защищённый диск. Рекомендуемый
ритм для первых пилотов — перед каждым развёртыванием и не реже одного раза в
неделю, пока в демо есть нужные данные.

## Проверка изоляции двух учреждений

Перед выдачей ссылки первым клиентам:

1. Создать два тестовых учреждения и сменить оба временных пароля.
2. В первом профиле создать программу с уникальным названием `Проверка A`.
3. Во втором профиле создать `Проверка B`.
4. Убедиться, что каждый профиль видит только свою программу и свои
   справочники.
5. Открыть программу первого профиля по её адресу из второго профиля: сервер
   должен вернуть «Программа не найдена», не данные первой организации.
6. Удалить обе тестовые программы и выйти из обоих профилей.

Автоматические тесты повторяют эту границу для программ, тем, периодов, групп и
справочников при каждой полной проверке `pnpm test`.

В production нужно дополнительно убедиться, что в логах запуска есть сообщение
`Runtime database role is restricted`. Сервер с
`REQUIRE_RESTRICTED_DATABASE_ROLE=true` не запустится, если `DATABASE_URL`
принадлежит владельцу базы, суперпользователю или роли с `BYPASSRLS`.

## Еженедельная проверка пилота

- открыть `/api/healthz` и получить `status: ok`;
- выполнить `pnpm demo:cleanup` и просмотреть очередь;
- проверить срок Neon Free и объём базы;
- создать и вынести резервную копию;
- убедиться, что кнопка покупки открывает Telegram `@SyncMaster3000`;
- просмотреть обращения пользователей и выдать доступ только согласованным
  учреждениям.
