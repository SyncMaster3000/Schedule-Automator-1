# Авторизация веб-демонстрации

## Реализованный сценарий

Сервер поддерживает полный жизненный цикл временной демонстрационной учётной записи:

- служебное создание отдельного пространства учреждения и первого пользователя;
- вход по логину и паролю;
- защищённая cookie-сессия;
- получение текущего пользователя и срока демонстрации;
- обязательная смена выданного временного пароля;
- немедленный выход с отзывом сессии;
- автоматический отказ во входе после окончания демонстрации.

При смене пароля текущая сессия сохраняется, а остальные сессии пользователя отзываются. Пароль и исходный токен сессии в PostgreSQL не сохраняются.
Повторные неверные попытки входа временно блокируются.

## HTTP API

| Метод  | Путь                        | Назначение                                   |
| ------ | --------------------------- | -------------------------------------------- |
| `POST` | `/api/auth/login`           | Вход и выдача защищённой cookie              |
| `GET`  | `/api/auth/me`              | Текущий пользователь, учреждение и срок демо |
| `POST` | `/api/auth/change-password` | Смена временного пароля                      |
| `POST` | `/api/auth/logout`          | Отзыв текущей сессии и удаление cookie       |
| `POST` | `/api/admin/demo-accounts`  | Создание демо-пространства и пользователя    |

Служебный маршрут создания аккаунта принимает заголовок `Authorization: Bearer ...`. Значение сравнивается с переменной `DEMO_ADMIN_TOKEN`; токен должен содержать не менее 32 байт.

## Настройки сервера

- `DATABASE_URL` — подключение к PostgreSQL.
- `SCHEDULE_STORAGE=postgres` — запрещает веб-серверу использовать локальную базу расписаний.
- `DEMO_ADMIN_TOKEN` — секрет создания демонстрационных аккаунтов.
- `PORT` — порт HTTP-сервера.
- `NODE_ENV=production` — включает cookie `Secure`; рабочий сайт должен обслуживаться только по HTTPS.

Начальная миграция находится в `lib/db/migrations`. Она создаёт организации, пользователей, роли, сроки демонстрации, сессии и аудит.

## Границы текущего этапа

Авторизация готова на сервере и покрыта модульными тестами. Программы и
основные справочники уже используют PostgreSQL и получают организацию только
из проверенной сессии. Остальные каналы расписаний закрыты до переноса: они не
могут использовать локальное SQLite-ядро в веб-режиме.
