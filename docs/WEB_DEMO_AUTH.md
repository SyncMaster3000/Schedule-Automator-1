# Авторизация веб-демонстрации

## Реализованный сценарий

Сервер поддерживает полный жизненный цикл временной демонстрационной учётной записи:

- служебное создание отдельного пространства учреждения и первого пользователя;
- вход по логину и паролю;
- защищённая cookie-сессия;
- получение текущего пользователя и срока демонстрации;
- обязательная смена выданного временного пароля;
- немедленный выход с отзывом сессии;
- автоматический отказ во входе после окончания демонстрации.

При смене пароля текущая сессия сохраняется, а остальные сессии пользователя отзываются. Пароль и исходный токен сессии в PostgreSQL не сохраняются.
Повторные неверные попытки входа временно блокируются.

## HTTP API

| Метод  | Путь                        | Назначение                                   |
| ------ | --------------------------- | -------------------------------------------- |
| `POST` | `/api/auth/login`           | Вход и выдача защищённой cookie              |
| `GET`  | `/api/auth/me`              | Текущий пользователь, учреждение и срок демо |
| `POST` | `/api/auth/change-password` | Смена временного пароля                      |
| `POST` | `/api/auth/logout`          | Отзыв текущей сессии и удаление cookie       |
| `POST` | `/api/admin/demo-accounts`  | Создание демо-пространства и пользователя    |
| `POST` | `/api/admin/demo-cleanup`   | Просмотр или удаление данных после хранения  |

Служебный маршрут создания аккаунта принимает заголовок `Authorization: Bearer ...`. Значение сравнивается с переменной `DEMO_ADMIN_TOKEN`; токен должен содержать не менее 32 байт.

Маршрут очистки использует тот же токен. Без точного подтверждения
`DELETE_EXPIRED_DEMOS` он работает только как предварительный просмотр и ничего
не удаляет. Штатно очистка выполняется фоновым процессом сервера.

## Создание аккаунта оператором

После публикации сервера задайте `DEMO_API_URL` и тот же `DEMO_ADMIN_TOKEN`,
который хранится в настройках сервера. Затем выполните:

```text
pnpm demo:create -- --organization "Название учреждения" --login demo.user --name "Имя пользователя"
```

Команда сама создаёт стойкий временный пароль, отдельное пространство
учреждения и семидневный доступ. Срок можно изменить параметром `--days`
в пределах от 1 до 30 дней. Пароль показывается оператору один раз и в базе
в открытом виде не хранится.

Проверить очередь на удаление без изменения данных:

```text
pnpm demo:cleanup
```

Подтвердить удаление только тех организаций, чей срок хранения уже истёк:

```text
pnpm demo:cleanup -- --confirm
```

## Настройки сервера

- `DATABASE_URL` — подключение ограниченной рабочей роли PostgreSQL.
- `MIGRATION_DATABASE_URL` — подключение владельца базы только для миграций.
- `REQUIRE_RESTRICTED_DATABASE_ROLE=true` — запрещает production-запуск под
  ролью, способной обходить RLS.
- `SCHEDULE_STORAGE=postgres` — запрещает веб-серверу использовать локальную базу расписаний.
- `DEMO_ADMIN_TOKEN` — секрет создания демонстрационных аккаунтов.
- `DEMO_API_URL` — адрес опубликованного API для операторской команды.
- `DEMO_CLEANUP_ENABLED` — включает фоновую очистку (по умолчанию `true`).
- `DEMO_CLEANUP_INTERVAL_HOURS` — период проверки от 1 до 24 часов.
- `DEMO_CLEANUP_BATCH_SIZE` — число организаций в одной транзакции, от 1 до 100.
- `SALES_CONTACT_URL` — ссылка кнопки приобретения десктопной версии; можно
  менять без пересборки приложения.
- `PORT` — порт HTTP-сервера.
- `NODE_ENV=production` — включает cookie `Secure`; рабочий сайт должен обслуживаться только по HTTPS.

Начальная миграция находится в `lib/db/migrations`. Она создаёт организации, пользователей, роли, сроки демонстрации, сессии и аудит.

## Границы текущего этапа

Авторизация, пользовательские страницы и жизненный цикл веб-демо готовы и покрыты
автоматическими проверками. Программы, справочники и расписания используют
PostgreSQL и получают организацию только из проверенной сессии. Веб-режим не
может обратиться к локальному SQLite-ядру настольной программы.

Для публикации остаётся подключить рабочий PostgreSQL, применить миграции,
задать секреты сервера, адрес для связи по вопросу покупки и выполнить
сквозную проверку на опубликованном HTTPS-адресе.

Порядок публикации описан в `WEB_DEMO_DEPLOYMENT.md`, повседневные действия
оператора — в `WEB_DEMO_OPERATIONS.md`.
