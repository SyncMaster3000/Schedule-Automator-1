# Контекст проекта Schedule Automator

Этот файл — постоянная память проекта. Его следует обновлять вместе с изменением
правил продукта. Репозиторий можно целиком открыть как хранилище Obsidian: ссылки
между Markdown-файлами будут работать без отдельной базы данных и сохранятся в Git.

## Где находится рабочее приложение

- `artifacts/schedule` — интерфейс Vue 3.
- `artifacts/api-server` — сервер Express, SQLite/`sql.js`, импорт и экспорт DOCX.
- `schedule-app` — устаревшая версия, её не дорабатывать.
- Рабочая ветка: `claude/schedule-automation-back-button-1cjnbz`.

## Основные правила учебного расписания

1. Для одной темы, определяемой сочетанием «исходный УТП + номер + название»,
   лекция должна полностью предшествовать практическому, семинарскому занятию,
   круглому столу и другим нелекционным видам. В групповом расписании правило
   проверяется отдельно для каждой группы.
2. Зачёт, экзамен и собеседование занимают 6 учебных часов: три последовательных
   двухчасовых слота в пределах одного календарного дня. Автопланировщик не имеет
   права разрывать этот блок между днями.
3. Аттестация ставится только после прохождения всех обычных занятий того УТП,
   к которому относится аттестационная строка. В групповом расписании готовность
   определяется отдельно для каждой группы.
4. При нескольких загруженных УТП их занятия нужно чередовать, а не исчерпывать
   планы по очереди. В течение одного дня обычно используются разные дисциплины.
5. При двух группах общая лекция по умолчанию создаётся одной записью для обеих
   групп. Практические занятия одной темы не следует одновременно назначать обеим
   группам. Максимальное количество групп в текущей модели — две.
6. Устойчивый ключ источника темы хранится в `program_topics.utp_source`, понятное
   пользователю название плана — в `utp_name`, исходное имя файла — в
   `utp_source_file`. Эти поля отделяют одинаково пронумерованные темы из разных
   загруженных документов. Для старых данных источник выводится безопасно из
   имеющихся полей без обязательного изменения записей в базе.

Подтверждение этих правил по образцам: [SAMPLE_SCHEDULE_PATTERNS_2025.md](SAMPLE_SCHEDULE_PATTERNS_2025.md).

## Остальные устойчивые договорённости

- Все сохранённые сейчас расписания являются тестовыми; их можно изменять и
  удалять при проверках.
- В групповом режиме поддерживается не более двух групп.
- Самоподготовка и итоговые виды занятий имеют специальные правила отображения
  при экспорте DOCX; не сводить их к обычным строкам таблицы.
- В групповом DOCX светло-серый цвет `D9D9D9` применяется только к строке второй
  группы при разных занятиях в одном временном интервале и только к диапазону
  от группового столбца до места проведения. Общие и совпадающие занятия
  остаются белыми.
- Шапка таблицы DOCX показывается только в начале таблицы. Не связывать строки
  дня через `keepNext`, не запрещать разбиение строк данных и не рассчитывать
  искусственные страничные блоки: таблица должна естественно продолжаться на
  следующей странице и оставаться свободно редактируемой в Word.
- При ожидаемом естественном переносе внутри дня заново начинать только
  вертикальное объединение даты, дня и времени, не создавая разрыв страницы.
  Если в части дня остаётся одна строка, дату и день выводить читаемо в одной
  объединённой ячейке на ширину двух служебных столбцов.
- При ожидаемом естественном переносе внутри дня заново начинать только
  вертикальное объединение даты, дня и времени, не создавая разрыв страницы.
  Если в части дня остаётся одна строка, дату и день выводить читаемо в одной
  объединённой ячейке на ширину двух служебных столбцов.
- В групповом DOCX дата и день недели объединяются только между строками групп
  одного временного интервала. Поэтому контекст дня остаётся видимым после
  естественного переноса таблицы без ручного расчёта границ страниц.
- Для белорусскоязычных УТП «Суразмова» означает «Собеседование» и также занимает
  6 учебных часов.
- Даты утверждения и подписания вводятся при утверждении расписания.
- Утверждённые и архивные снимки имеют независимый жизненный цикл: удаление
  рабочей программы удаляет её темы, периоды, занятия, временные изменения и
  обычные сохранённые версии, но не удаляет записи архива. Название исходной
  программы хранится в самой архивной записи и полном снимке.
- Исключённые пользователем даты хранятся в настройках периода и не участвуют
  в заполнении сетки или автопланировании до явного восстановления.
- Учебная неделя (Пн–Пт/Пн–Сб) и режим пустых слотов выбираются в форме
  создания или редактирования периода, до перехода в конструктор расписания.
- Отмена заполнения сетки относится только к последней операции и удаляет лишь
  созданные ею пустые слоты, которые после заполнения не редактировались.
- Рабочую БД `artifacts/api-server/schedule-data/schedule.db` никогда не включать
  в коммит: она содержит локальные тестовые данные пользователя.

## Проверка изменений автопланировщика

Минимальная проверка перед публикацией:

1. Запустить тесты `autofillPlanner.test.mjs`.
2. Собрать сервер и выполнить его проверку типов.
3. Собрать интерфейс.
4. На временной программе проверить одиночный и групповой режимы через API или UI.
5. Удалить временную программу; локальную БД не добавлять в Git.

## Обновление контекста

При появлении нового подтверждённого правила следует добавить его сюда. Наблюдения
из образцов сначала фиксируются в `SAMPLE_SCHEDULE_PATTERNS_2025.md`, а продуктовые
решения — в этом файле. Так контекст остаётся рядом с кодом, проходит ревью и не
зависит от конкретного компьютера или установки Obsidian.
