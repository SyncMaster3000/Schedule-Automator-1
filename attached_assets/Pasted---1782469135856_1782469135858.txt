Дополнительное ТЗ по доработке конструктора расписания
Цель: повысить удобство работы с конструктором расписания без изменения существующего функционала и архитектуры приложения.
1. Массовые операции с занятиями
•	Добавить возможность одновременно перетаскивать, перемещать и заменять все выделенные занятия с сохранением их взаимного порядка.
•	при массовом редактировании занятии добавить возможность присвоения номера (названия) группы у которых будет проходить это занятие, а не только выбор преподавателей и аудитории
2. Оформление интерфейса
•	Заменить темное фоновое изображение на светлую палитру (светло-синие оттенки).
•	Обеспечить высокую читаемость текста при любом размере окна.
•	Во всем интерфейсе программы использовать только букву «е» вместо буквы «ё».
3. Визуальное отображение изменений
•	Все изменения, внесенные после первоначального создания расписания, должны быть сразу заметны непосредственно в расписании.
•	Измененные занятия должны иметь небольшую цветовую метку или значок.
•	При наведении курсора отображать краткую информацию:
o	что изменено;
o	когда изменено;
•	При открытии карточки занятия отображать полную историю изменений в хронологическом порядке.
•	Предусмотреть возможность скрыть или очистить отметку об изменении после просмотра.
4. Временные изменения расписания
•	Добавить возможность создавать временные изменения расписания без изменения утвержденной версии.
•	Пользователь должен иметь возможность указать период действия изменения (одна дата или диапазон дат).
•	После окончания указанного периода автоматически восстанавливается первоначальное расписание.
•	Временные изменения должны поддерживать:
o	замену преподавателя;
o	замену аудитории;
o	замену занятия;
o	перенос времени занятия;
o	отмену занятия;
o	добавление дополнительного занятия.
•	Все временные изменения должны отображаться в истории изменений.
5. Массовое смещение расписания
•	Добавить функцию смещения занятий вниз на один или несколько таймслотов.
•	Пользователь должен иметь возможность сместить:
o	все расписание;
o	отдельную неделю;
o	отдельный день.
•	После смещения верхние свободные таймслоты автоматически становятся пользовательскими слотами.
•	В эти слоты должна быть возможность быстро добавлять организационные мероприятия (регистрация участников, приветственное слово, открытие программы, инструктаж и другие).
•	При смещении должны сохраняться порядок занятий, преподаватели, аудитории и все остальные данные.
•	Если смещение невозможно из-за отсутствия свободных таймслотов, программа должна предупредить пользователя и не допустить потери занятий.
6. Архив расписаний
•	В архиве переименовать категорию «Краткосрочные курсы» в «Обучающие курсы».
7. Статусы занятий
•	Исключить статус «Частично нераспределенные занятия».
•	Использовать только два статуса:
o	«Распределенные»;
o	«Нераспределенные».
8. Возврат занятий в очередь
•	Если занятие удаляется из конструктора расписания, оно не должно удаляться из системы.
•	Такое занятие автоматически должно возвращаться в список нераспределенных занятий.
9. Автоматическое сохранение типа занятия
•	Если при создании расписания отключена опция «Заполнять задачами из очереди», то при ручном добавлении занятия автоматически использовать тип занятия из исходного УТП (лекция, семинар, практическое занятие, круглый стол, зачет, экзамен и т.д.).
•	Пользователь не должен повторно выбирать тип занятия.
10. Отмена и повтор действий
•	Добавить функции Undo и Redo для всех операций конструктора.
11. Закрепление
•	Добавить возможность закреплять:
o	отдельные занятия;
o	день;
o	неделю;
o	все расписание.
•	Закрепленные элементы не должны автоматически перемещаться или изменяться при любых автоматических операциях до снятия закрепления.
12. Работа со свободными таймслотами
•	Для любого свободного таймслота добавить контекстное меню со следующими действиями:
o	Добавить организационное мероприятие.
o	Добавить занятие из списка нераспределенных.
o	Создать новое пользовательское занятие.
o	Добавить самоподготовку.
o	Оставить слот пустым.
Общие требования
•	Не изменять существующий функционал программы.
•	Не переписывать работающие модули без необходимости.
•	Использовать существующую архитектуру приложения.
•	Все новые функции должны быть полностью совместимы с уже реализованным конструктором расписания.
•	Не допускать потери занятий УТП при любых действиях пользователя.
•	Перед завершением доработки выполнить проверку совместимости всех существующих функций и убедиться, что новый функционал не нарушил работу программы.
