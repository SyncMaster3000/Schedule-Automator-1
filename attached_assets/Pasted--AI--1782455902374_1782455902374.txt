Техническое задание (оптимизированная версия для AI)

Цель: доработать систему создания расписаний без изменения существующего функционала. Сохранять обратную совместимость.

1. Типы занятий
- Добавить тип «Круглый стол».
- Добавить произвольный тип занятия (ввод пользователем + автодополнение).

2. Преподаватели
- Добавить «Приглашённых преподавателей/экспертов».
- Они не участвуют в проверке конфликтов и не индексируются системой накладок.

3. Конструктор расписания (критично)
- Для каждого дня всегда отображать полный набор таймслотов.
- Пустые слоты: либо пустой блок, либо «Самоподготовка» (настройка пользователя).
- Пустые блоки можно переименовывать, превращать в организационные занятия и использовать как цель drag-and-drop.
- При переносе занятия:
  * поддерживать push-down (смещение вниз);
  * поддерживать swap (обмен местами).
- Занятия из УТП никогда не удаляются и не теряются, только перераспределяются.
- Разрешить замену занятия на элемент из списка нераспределённых:
  * заменяемое занятие уходит в нераспределённые;
  * выбранное из нераспределённых занимает его место.
- Поддержать создание одного расписания из нескольких УТП.

4. Учебная неделя
- Режимы: Пн–Пт и Пн–Сб.

5. Расписание для двух групп
- Режим «Групповое расписание».
- Лекции по умолчанию общие для двух групп.
- Настройка: «Проводить лекции раздельно».
- Практические/семинары не должны дублироваться одновременно.
- Для нелекционных занятий в одном слоте отображать отдельные занятия групп А и Б (должна быть возможность пользовательского ввода номера учебной группы.

6. Архив
После утверждения расписания выбирать раздел:
- Повышение квалификации;
- Переподготовка;
- Краткосрочные курсы.

7. UI
- Удалить дублирующую кнопку импорта УТП.
- Заголовок «Учебные программы» заменить на «Создание расписания».
- Термины «программа/учебная программа» заменить на «расписание» по контексту.

8. Проверка конфликтов
- Исправить сквозную проверку по всем расписаниям.
- Проверять преподавателей и аудитории по дате/времени.
- Показывать конфликт и название расписания-источника.

9. Массовое редактирование групп
- Массовое и одиночное редактирование выбранных учебных групп.

10. Дополнительно
- Современный drag-and-drop UI.
- Хранение данных в SQLite.
- Защита от потери занятий при любых операциях.
- Визуальная подсветка конфликтов (красный цвет, tooltip).

11. Дизайн
- Заменить тёмный фон на светло-синюю палитру.
- Сохранить высокую читаемость текста.

12. История изменений
- Добавить заметки/комментарии к расписанию.
- Фиксировать изменения (замены занятий, преподавателей и др.) с датой и автором.

Требования к разработке:
- Не удалять существующие функции.
- Минимизировать объём изменений в архитектуре.
- Использовать существующие компоненты и модели данных, где возможно.
- Все новые функции должны быть совместимы с текущей логикой приложения.
